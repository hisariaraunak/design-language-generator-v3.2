# Component Library — Domain-Neutral Core

## Mandatory boundary
Source screenshot domain vocabulary is demo content only. Core names/APIs describe UI structure, interaction or presentation. Product-specific composites go in `extensions/<domain>/`.

## Foundations
Color, Typography, Spacing, Shape, Elevation, Stroke, Motion, Iconography, Imagery.

## Primitives
Text, Heading, Icon, Image, Divider, Surface, Stack, Inline, Grid, Container, Scrim, AtmosphericField.

## Controls
Button, IconButton, Link, TextField, TextArea, SearchField, Select, Checkbox, Radio, Switch, Slider, Stepper, SegmentedControl, SelectionRow.

## Navigation
TopBar, BottomNavigation, NavigationRail, Tabs, Breadcrumb, Pagination, StepNavigation.

## Content
EditorialHero, NarrativeBlock, Card, MediaCard, List, ListRow, Avatar, Badge, Chip, Tag, Metric, MetricGroup, Timeline, Accordion, Callout.

## Feedback
Toast, Snackbar, Alert, InlineStatus, Tooltip, Popover, Dialog, Drawer, BottomSheet, ProgressIndicator, Skeleton, EmptyState, ErrorState, LoadingState, Confirmation.

## Data
ChartFrame, LineChart, AreaChart, BarChart, Donut, Sparkline, Gauge, RangeBar, Table, DataTable, Legend, ChartAnnotation, DataTooltip, MetricDelta.

## Patterns
Form, SearchResults, FilterPanel, DataExplorer, DashboardSection, DetailHeader, SettingsSection, ActivityFeed, MasterDetail, ConfirmationFlow, EditorialSummary.

Every component must provide anatomy, variants, sizes, states, behavior, tokens, content rules, accessibility, do/don't, motion and platform notes.

Phase 6 exit: `domain_neutrality_validation=pass`.

## Iconography
Define Icon, IconButton, semantic registry (100+ common-app icons), sizes, optical rules, RTL and accessibility.
